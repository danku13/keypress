# keypress

Показывает на экране нажатия клавиш, кнопки мыши и прокрутку колесика.
Минималистичный аналог Keystro (https://keystro.app/) для личного использования.
Windows 10/11 (64-бит), Rust + egui.

## Возможности

- Плавающий виджет с нажатыми клавишами: комбо собираются в «Ctrl + C»,
  одиночный модификатор показывается сам, автоповтор не спамит
- Кириллица: когда активна русская раскладка, виджет показывает её символы
  («Ф» вместо «A»); настраивается галочкой «Кириллица»
- Кнопки мыши в том же виджете — SVG-иконкой в стиле «вид сбоку» (по мотивам
  freesvg.org left-click-right-click): нажатая кнопка подсвечена цветом кликов,
  «СКМ» — подсветка колёсика; иконка комбинируется с модификаторами
  («Ctrl + [иконка мыши]», удобно для записи демо с хоткеями вида Ctrl + ЛКМ)
- Прокрутка колесика дублируется в виджет: иконка мыши со стрелкой вверх над
  колёсиком / вниз под ним, в цвете прокрутки; во время долгого скролла строка
  продлевается, а не гаснет посреди прокрутки (троттлинг 250 мс)
- Режим «кейкапы» (включается галочкой, по умолчанию выключен): каждая
  клавиша рисуется SVG-кейкапом «вид сверху», комбо выглядит как
  [Ctrl] + [Alt] + [C]; классический текст на фоне остаётся без изменений
- SVG-иконки мыши управляются независимо от режима кейкапов (галочка
  «Мышь и колесо — SVG-иконкой»): работают и в классике (иконка на бабле),
  и в кейкапах; корпус и контур мыши красятся отдельно от клавиш
- Кастомные кейкапы: любая картинка (PNG/JPG/GIF/BMP/ICO/SVG) вместо
  стандартного кейкапа — общая для всех клавиш и/или по-клавишные
  (перекрывают общую); относительные пути — от папки с keypress.toml
- Позиционирование текста на кейкапах: размер текста, сдвиг X/Y (для
  кастомных картинок с нестандартным местом под символ) + высота кейкапа
- Количество строк в виджете настраивается: слайдер «Строк в виджете» (1–10)
- Иконка в системном трее: показывает, что keypress запущен. Левый клик —
  пауза/показ, двойной — открыть настройки, правый — меню (пауза с галочкой,
  настройки, выход); иконка синий кейкап с K, рисуется кодом; переживает
  перезапуск explorer (TaskbarCreated); отключается галочкой «Системный трей»
  или ключом `tray_icon = false` в keypress.toml (применяется на лету)
- Эффект на клик мыши у курсора: круг / кольцо / квадрат — на выбор, с цветом
- Индикатор прокрутки у курсора (треугольник вверх/вниз)
- Панель настроек: размер, позиция X/Y, форма и цвета, время показа;
  цвет редактируется пикером (непрозрачный RGB) + отдельным слайдером
  «Непрозрачность» — прежний смешанный пикер портит полупрозрачные цвета
- Настройки применяются на лету, хранятся в `keypress.toml` рядом с exe;
  если папка exe защищена от записи (UIAccess-установка в Program Files) —
  в `%APPDATA%\keypress\keypress.toml`; переопределяется переменной
  `KEYPRESS_CONFIG`
- Горячие клавиши: `Ctrl+Alt+K` — пауза/показ, `Ctrl+Alt+Q` — выход
  (то же самое доступно через иконку в трее: левый клик — пауза,
  меню по правому клику — выход)

## Сборка и запуск

1. Поставь Rust: https://rustup.rs (на Windows — тулчейн по умолчанию, MSVC,
   плюс «Desktop development with C++» из Visual Studio Build Tools).
2. В папке проекта:

```bat
cargo run --release                 :: оверлей + панель настроек
cargo run --release -- --settings   :: только панель настроек
```

Либо собери один exe: `cargo build --release` → `target\release\keypress.exe`.

При обычном запуске exe открываются **и панель настроек, и оверлей** —
контроль сразу виден. Если оверлей уже запущен, повторный запуск просто
покажет панель (второй оверлей не создастся). В панели есть кнопки
«Запустить оверлей» / «Остановить оверлей», статус оверлея отображается.

## Оверлей над меню Пуск (UIAccess-сборка)

Меню Пуск на Windows 11 живёт в защищённой shell-полосе z-порядка ВЫШЕ
обычных topmost-окон, поэтому обычная сборка под Пуском не видна. Процесс
с `uiAccess="true"` в манифесте получает собственную полосу выше полосы
оболочки (так работает osk.exe). Сборка такой версии — скрипт из папки
проекта в PowerShell **от имени администратора**:

```powershell
.\make-uiaccess.ps1
```

Он: собирает exe с манифестом (`KEYPRESS_UIACCESS=1 cargo build --release`,
вшивку манифеста делает build.rs через winresource), создаёт самодписанный
сертификат подписи кода и доверяет ему локально, подписывает exe и кладёт в
`C:\Program Files\keypress\` (требование Windows: uiAccess-exe должен быть
подписан и лежать в защищённой папке — иначе не запустится вовсе).
Обычная сборка манифест не вшивает и ведёт себя как раньше.

## Кастомные кейкапы

В панели настроек группа «Кейкапы»: путь к общей картинке-кейкапу и
по-клавишные картинки («Клавиша» = «Файл», регистр имени не важен).
Порядок разрешения для клавиши: точное имя в по-клавишных → то же без
учёта регистра → общая картинка → стандартный SVG-кейкап. Относительный
путь считается от папки с `keypress.toml`; картинка растягивается на
размер кейкапа (высота регулируется слайдером «Высота кейкапа»), подпись
рисуется egui поверх картинки — её размер и сдвиг настраиваются
слайдерами «Текст на кейкапе» (X вправо, Y вниз, в точках).

Пример блока в keypress.toml:

```toml
keycap_height = 1.2
keycap_image = "caps/base.png"           # общая для всех клавиш
keycap_text_dx = 0.0
keycap_text_dy = 2.0
keycap_text_scale = 0.9

[keycap_images]                           # перекрывают общую
"A" = "caps/a.png"
"Пробел" = "caps/space.png"
```

## Тесты (TDD)

Чистая логика (агрегация комбо, VK-имена, кириллица, мышь/колесо в виджете,
фильтр инжекций, математика эффектов, конфиг, разбор аргументов) вынесена
в кроссплатформенные модули и покрыта unit-тестами. Тесты не требуют Windows:

```bat
cargo test                          :: 99 тестов: config, color, icons, keys, input, fx, main, zorder, tray
```

SVG-иконки (мышь/кейкапы) генерируются кодом (src/icons.rs); для ручной
визуальной проверки: `cargo test -- --ignored dump_svgs --nocapture`, потом
файлы из /tmp/keypress-svg можно открыть в браузере.

Окно-специфичный клей (hooks/winutil/overlay/settings) проверяется
компиляцией: `cargo check --target x86_64-pc-windows-gnu`.

## Как это устроено

- Поток хуков: `SetWindowsHookEx(WH_KEYBOARD_LL / WH_MOUSE_LL)` — только
  наблюдение, ввод никогда не глотается (`CallNextHookEx` всегда).
- Оверлей: прозрачное always-on-top окно на весь экран (borderless),
  клик-тру = `with_mouse_passthrough(true)` (winit сам держит
  `WS_EX_LAYERED | WS_EX_TRANSPARENT`) + подстраховка каждый кадр тем же
  набором через `SetWindowLongPtrW`. Важно: клик-тру работает только
  в паре `WS_EX_LAYERED | WS_EX_TRANSPARENT` — один `WS_EX_TRANSPARENT`
  без LAYERED перехватывает клики (это и был баг v0.1).
- Ещё одна ловушка слоёных окон: `WS_EX_LAYERED`-окно вообще не рисуется,
  пока для него не вызваны `SetLayeredWindowAttributes`/
  `UpdateLayeredWindow`. winit 0.29.15 атрибуты слоёв не задаёт, поэтому
  `apply_overlay_styles()` каждый кадр вызывает
  `SetLayeredWindowAttributes(hwnd, 0, 255, LWA_ALPHA)` — без этого оверлей
  после включения клик-тру становился полностью невидимым (баг v0.2),
  а с ним рисуется нормально и пер-пиксельная прозрачность egui
  сохраняется.
- Оверлей и меню Пуск: winit ставит `HWND_TOPMOST` один раз при создании
  окна и больше не поднимает, а Пуск/Поиск (CoreWindow оболочки) при
  открытии вставляются в topmost-группу выше нашего NOACTIVATE-окна.
  Поэтому `apply_overlay_styles()` каждый кадр переутверждает
  `SetWindowPos(hwnd, HWND_TOPMOST, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)`:
  оверлей поднимается над Пуском и не крадёт фокус (баг v0.3).
  Если на конкретной машине Пуск всё равно выше (Win11 держит CoreWindow
  в защищённой полосе) — см. раздел «Оверлей над меню Пуск (UIAccess-сборка)».
- Кастомные кейкапы: raster-форматы декодируются крейтом `image` напрямую
  в `ColorImage` (без ImageLoader-магии egui_extras), SVG — через svg-лоадер
  (тот требует URI с расширением `.svg`). Ключ кеша текстур —
  FNV-1a(путь + mtime + размер) + размер растра: заменил файл на диске —
  текстура перестроится без перезапуска.
- Диагностика z-порядка: запуск с `KEYPRESS_DEBUG=1` ведёт
  `keypress-zdebug.log` рядом с `keypress.toml` — какие окна выше оверлея
  (класс + заголовок + пересечение), пишется только при изменениях.
  Модуль `zorder.rs` распознаёт shell-классы (CoreWindow = Пуск/Поиск,
  Shell_TrayWnd и др.); если на конкретной системе Пуск всё же перекрывает
  оверлей, лог покажет виновника.
- Системный трей: отдельный поток с message-only окном (`HWND_MESSAGE`),
  `Shell_NotifyIconW` шлёт события мыши в его WndProc; тот превращает их в
  `UiEvent` (TogglePause/Quit) и кладёт в общий с хуками crossbeam-канал —
  оверлей разбирает их в `drain_events()`, без новых глобальных состояний.
  Иконка рисуется кодом (32x32 BGRA → `CreateDIBSection` →
  `CreateIconIndirect`), перезапуск explorer ловится через
  `RegisterWindowMessage("TaskbarCreated")`, при выходе `shutdown()` шлёт
  WM_CLOSE в окно трея — иконка удаляется в WM_DESTROY, а не висит призраком.
- Кириллица: на каждое нажатие хук берёт раскладку окна переднего плана
  (`GetForegroundWindow` → `GetWindowThreadProcessId` → `GetKeyboardLayout`)
  и разрешает символ через `ToUnicodeEx`; если настройка включена и символ
  кириллический — показывается он (в верхнем регистре), иначе имя из
  VK-таблицы. Флаг живёт в `AtomicBool` и меняется панелью/перечитыванием
  конфига на лету.
- Мышь в виджете: кнопки (ЛКМ/ПКМ/СКМ) и прокрутка идут через общий
  `KeyAggregator`, поэтому корректно комбинируются с зажатыми
  модификаторами («Ctrl + ЛКМ», «Ctrl + Колесо ↓»); колесо троттлится
  (250 мс на одно направление), нажатие колеса = СКМ.
- Рендер: egui (wgpu). Конфиг: `toml`, оверлей перечитывает файл по mtime.
- Модули: `keys.rs`/`input.rs`/`fx.rs` — чистая логика без Win API,
  `tray.rs` — кроссплатформенная логика меню/иконки + Windows-клей,
  `hooks.rs`/`winutil.rs`/`overlay.rs`/`settings.rs` — Windows-клей.

## Известные ограничения MVP

- Только основной монитор: события за его пределами не отрисовываются.
- Поверх exclusive-fullscreen игр виджет не виден (borderless / оконный — ок).
- Ввод в приложениях, запущенных от администратора, виден только если
  сама программа тоже запущена от администратора (UIPI).
- При выключенной настройке «Кириллица» имена клавиш всегда английские.
- Боковые кнопки мыши (X1/X2) в виджете не показываются.
- Позиция виджета задаётся процентами экрана, а не перетаскиванием мышью.
